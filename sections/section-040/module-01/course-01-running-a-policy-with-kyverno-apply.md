# Running a Policy with kyverno apply

A policy written for a cluster is hard to check by hand. You would have to apply it, create resources, read reports and then clean up. The `kyverno apply` command removes that loop: it reads a policy file and a resource file from disk and tells you what the policy would do. This part shows the command, its output and the flags you will use most.

## The basic command

`kyverno apply` takes one or more policy paths and one or more resource paths. A path can be a file or a directory.

```sh
kyverno apply require-limits.yaml --resource pods.yaml
```

The command evaluates every rule in the policy against every resource that matches it. It prints one line for each failing rule, with the policy name, the rule name and the message from the policy. At the end it prints a summary line with the number of passes, failures, warnings, errors and skips.

The five counts use the same meaning as in a `PolicyReport`. A pass means the resource satisfied the rule. A fail means it did not. A warn appears when the policy is not scored. An error means the rule could not run. A skip means the rule matched but a precondition or exception stopped it.

## Exit code

`kyverno apply` exits with a non-zero code when a resource violates a rule in `Enforce` mode. The flag `--audit-warn` treats failures of `Audit` policies as warnings. A policy that is in `Audit` mode therefore does not always change the exit code. Read the counts when you need to know about every failure. For a gate that states what you expect, prefer `kyverno test`, which compares each result with an expectation.

## Useful flags

- `--resource` (`-r`) selects the resource files. Give the flag more than once for more files.
- `--cluster` reads live resources from the cluster in your current kubeconfig context instead of files.
- `--namespace` (`-n`) sets the namespace for namespaced resources that do not declare one.
- `--detailed-results` prints a line for every rule result, including passes.
- `--policy-report` prints the result as a `PolicyReport` object instead of text.
- `--values-file` (`-f`) loads variable values. The next parts use it.
- `--set` (`-s`) sets a single variable on the command line, for example `--set request.operation=UPDATE`.
- `--output` writes mutated or generated resources to a file or directory.

## Mutation and generation

For a mutate rule, `kyverno apply` prints the patched resource. For a generate rule, it can print the resource that would be created. Neither writes anything to a cluster. This is what makes the command safe to run on a laptop.

> [!TIP]
> **Try it - see a failure and a pass**
>
> In the playground working directory, run `kyverno apply policy.yaml --resource resources.yaml --detailed-results`. Find the Pod that fails and the Pod that passes. Then fix the failing Pod in the resource file and run the command again.

## Common pitfalls

- Passing the resource file with a name that does not match the policy's `match` block. The rule never matches, so the output shows nothing and looks like a pass. Check the counts, not only the absence of errors.
- Assuming a zero exit code means all resources pass. Failures of `Audit` policies are reported in the output and do not always change the exit code.
- Testing against a Deployment when the policy matches Pods. Autogenerated rules cover this case for validate rules in a cluster, and the CLI applies them too, but a rule written for another kind does not.

Now you can run a policy once and read what it reports. The next step is to make the expected result part of a file, so a machine can compare it to the actual result every time.
